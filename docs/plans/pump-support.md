# v0.2.0 水泵支持计划

状态：**计划中**。下一版优先完成 Windows + LibreHardwareMonitor（LHM）下的一台真实水泵，从识别、读取到受限控制及恢复的完整验收。当前没有已验证的水泵型号。

版本关系、发行包和验证记录统一登记在 [版本树](../versions.md)。本计划的完成条件是可复查的设备行为；模拟器结果只证明软件逻辑。

## 已有基础

| 能力 | 当前证据 | 下一版需要补齐 |
|---|---|---|
| 水泵设备类型、RPM 和占空比 | DeviceType::Pump、pump.rpm、pump.speed_percent 已存在 | 在 CLI 和界面中准确显示泵名称、单位和可写状态 |
| 自动化与保护 | 现有规则引擎和泵最低占空比保护可复用；v0.1.1 修复渐变和热紧急优先级缺口 | 以目标设备证据确定控制范围，检查所有写入入口 |
| LHM 读写与设定值回读 | 适配器已有 HTTP 读写；当前根据名称中的 pump 识别，并按编号配对 RPM 与 Control | 明确设备身份和通道对应关系，避免因名称或枚举顺序变化而写错通道 |
| 模拟设备 | 已有泵、拒写、未知结果和断连模拟 | 增加停转、RPM 丢失和恢复场景；当前模拟泵未接入热模型 |
| Open Device Protocol | 协议可以描述泵；适配器仍使用模拟传输 | 真实 USB 传输作为后续独立工作 |

相关实现：[LHM 映射](../../adapters/libre-hardware-monitor/src/mapping.rs)、[写入与回读](../../adapters/libre-hardware-monitor/src/lib.rs)、[安全策略](../../crates/ohm-runtime/src/safety.rs)、[模拟器](../../adapters/mock/src/)。

## 开工信息

在首轮只读检测中记录以下信息，作为测试对象身份：

- 水泵品牌、型号；主板或控制器型号。
- 接法与控制模式：主板 PWM/DC 接口、USB 一体水冷控制器或独立控制器。
- Windows、LHM 和相关驱动版本。
- LHM 的设备路径、RPM 传感器路径和 Control 路径；记录是否可读、可写、可回读。
- 厂商提供或经验证的占空比范围、控制模式和恢复方法。

60% 是现有软件的默认泵保护值，不能作为所有型号的硬件要求。转速单位 RPM、请求占空比和设定值回读应分别记录。

## 分阶段验收

| 任务 | 软件验收 | 实机验收 | 完成证据 |
|---|---|---|---|
| PUMP-01 | 真实格式的脱敏 LHM 样本覆盖单泵、多通道、无编号、重名、重排与重连；歧义映射不开放控制 | 界面和 CLI 中的设备对应目标泵，RPM 与 LHM 一致 | 样本来源、自动化测试、设备清单 |
| PUMP-02 | 所有写入经过安全策略；低于下限的当前读数、正常渐变和热紧急都有回归测试；缺失回读保持未确认状态 | 在已确认的范围内改变设定值，分别记录回读和实际 RPM | 请求、结果、时间戳、RPM 和审计记录 |
| PUMP-03 | 先用模拟器覆盖零 RPM、丢失读数、拒写、断连及恢复；超时和故障状态可解释 | 验证正常停止与退出后的实际控制状态；恢复失败明确报告 | 故障用例报告、恢复前后读数 |
| PUMP-04 | Windows 构建、CLI 安装、UI 与回归测试通过 | 指定型号及接法完成测试，限制写入支持表 | 版本 tag、源码 SHA、环境、结论及证据链接 |

真实测试中的控制范围和恢复步骤必须先由目标设备信息确定。故障注入先在模拟器中完成；不要通过把真实泵设为零或拔除冷却设备来代替软件故障测试。

## v0.2.0 发布判据

- [ ] 一台明确型号和接法的水泵完成识别、RPM 读取与受限控制。
- [ ] 控制歧义、RPM 丢失及回读失败都有明确状态，不显示虚假的成功。
- [ ] 重连和传感器枚举重排不会把历史控制请求写到其他设备。
- [ ] 保护下限、热紧急、故障处理与退出恢复都有相应验证证据。
- [ ] Windows 安装和回归通过，支持表写清测试设备、模式、软件版本及限制。
- [ ] 真实发布完成后，版本管理工具把 tag、源码 SHA 和验证链接写入版本树。

USB 一体水冷厂商协议、真实 ODP 控制器、流量计、灯效和屏幕能力分别保留为后续分支；各自应有独立设备与验证范围。
